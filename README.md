# Лабораторная работа № 27. Шаблон MVC

**Тема индивидуального задания:** продажа билетов в кинотеатр.
**Тип приложения:** WPF App (.NET), C#, как в примере из методички.

Программа — это касса кинотеатра. Кассир выбирает фильм и сеанс, указывает ряд и место
(или щёлкает по месту на схеме зала) и тип билета. Программа считает стоимость с учётом
скидок и VIP-ряда, продаёт билет, показывает проданные билеты и выручку, умеет оформлять
возврат.

## Как открыть и запустить в Visual Studio

1. Нужна **Visual Studio 2022** (версия 17.8 или новее) с рабочей нагрузкой
   **«Разработка классических приложений .NET»** (.NET desktop development).
   Проверить: *Средства → Получить средства и компоненты*.
2. Скачать проект: на GitHub нажать **Code → Download ZIP** и распаковать
   (или клонировать: *Git → Клонировать репозиторий*).
3. Открыть файл **`Lab27_MVC.sln`** двойным кликом.
4. Нажать **F5** (или зелёную кнопку ▶ **CinemaTickets**). Окно кассы откроется.

> Если Visual Studio пишет, что не поддерживает .NET 8 (старая версия VS 2022),
> откройте `CinemaTickets/CinemaTickets.csproj` и замените
> `net8.0-windows` на `net6.0-windows`. Код работает и там.

## Где в коде Model, View и Controller

```
Lab27_MVC.sln
└── CinemaTickets/
    ├── App.xaml / App.xaml.cs      ← здесь создаются и связываются M, V и C
    │
    ├── Models/                     ← MODEL: данные и логика
    │   ├── CinemaModel.cs          ← "касса": расчёт цены, продажа, возврат, выручка
    │   ├── Movie.cs                ← фильм
    │   ├── Hall.cs                 ← зал (ряды, места, VIP-ряд)
    │   ├── Session.cs              ← сеанс (фильм + зал + время + занятые места)
    │   ├── Ticket.cs               ← проданный билет
    │   ├── TicketCategory.cs       ← типы билетов и скидки
    │   ├── PriceCalculation.cs     ← результат расчёта: цена и для какого места
    │   └── CinemaRuleException.cs  ← ошибка "нарушено правило кинотеатра"
    │
    ├── Views/                      ← VIEW: то, что видит пользователь
    │   ├── MainWindow.xaml         ← разметка окна
    │   ├── MainWindow.xaml.cs      ← UpdateView(): показать данные модели
    │   └── ICinemaView.cs          ← что контроллер может попросить у окна
    │
    └── Controllers/                ← CONTROLLER: обработка действий пользователя
        └── TicketController.cs     ← проверка ввода и передача данных модели
```

### Как части общаются

```
 Пользователь
     │ нажал «Продать билет»
     ▼
 ┌────────┐  текст из полей "Ряд", "Место",   ┌────────────┐
 │  VIEW  │ ───────────────────────────────►  │ CONTROLLER │
 │ (окно) │  выбранный тип билета             │  проверка  │
 └────────┘                                   └────────────┘
     ▲                                              │ данные верны:
     │ событие Changed:                             │ SellTicket(ряд, место, тип)
     │ «я изменилась» → UpdateView()                ▼
     │                                        ┌────────────┐
     └─────────────────────────────────────── │   MODEL    │
                                              │ цена, места│
                                              │  выручка   │
                                              └────────────┘
```

То же самое, что в методичке, только для кинотеатра:

| Методичка (калькулятор)                          | Эта программа (кинотеатр)                                     |
|--------------------------------------------------|---------------------------------------------------------------|
| `Num1TextBox`, `Num2TextBox`, кнопка «Посчитать» | поля «Ряд», «Место», тип билета, кнопки «Рассчитать», «Продать» |
| `CalculateButton_Click` — проверка ввода         | `TicketController.CalculatePrice / SellTicket` — проверка ввода |
| `Calculate(num1, num2)` — `result = num1 + num2` | `CinemaModel.CalculatePrice / SellTicket` — расчёт цены, продажа |
| `UpdateView()` — `ResultTextBlock.Text = result` | `MainWindow.UpdateView()` — цена, схема зала, таблица, выручка |

Отличие от методички: модель не вызывает `UpdateView()` окна напрямую, а сообщает
событием `Changed`, что изменилась. Окно подписано на это событие. Так модель
не зависит от окна (в методичке об этом сказано: «в приложениях модель может сама
уведомлять вид, что нужно что-то изменить»).

## Правила расчёта цены (в модели)

```
цена = базовая цена сеанса × коэффициент типа билета × 1,5 (если VIP-ряд)
```

* Базовая цена зависит от сеанса: утром дешевле (250 руб.), вечером дороже (450 руб.).
* Тип билета: взрослый — 100 %, студенческий — 80 %, пенсионный — 70 %, детский — 50 %.
* Последний ряд зала — VIP (диваны), цена × 1,5.
* Детский билет нельзя продать на фильм 12+ и 18+.
* Одно место на один сеанс нельзя продать дважды.

## Что проверяет контроллер (валидация ввода)

* Ряд и место не пустые.
* Ряд и место — целые числа (`abc`, `2.5` не пройдут).
* Ряд и место существуют в выбранном зале (например, в «Зале 1» 8 рядов по 12 мест).
* Выбран тип билета.
* При возврате выбран билет в таблице, и пользователь подтвердил возврат.

## Что показать преподавателю (сценарий проверки)

1. Запустить программу: выбран «Интерстеллар», сеанс 12:30, видна схема зала.
2. Щёлкнуть по месту в 3-м ряду → в полях подставятся ряд и место, цена **300 руб.**
3. Сменить тип билета на «Студенческий» → цена пересчитается: **240 руб.**
4. Щёлкнуть по месту в последнем (VIP) ряду → цена **360 руб.** (300 × 0,8 × 1,5).
5. Нажать «Продать билет» → место стало красным, билет появился в таблице, выросла выручка.
6. Нажать «Продать билет» ещё раз → ошибка «Место … уже продано» (правило модели).
7. Ввести в поле «Ряд» `abc` или `20` и нажать «Рассчитать стоимость» → ошибка ввода
   (проверка контроллера).
8. Выбрать фильм «Джокер» (18+) — поля «Ряд»/«Место» очистятся, потому что сменился зал.
   Выбрать тип «Детский» и щёлкнуть по любому месту → ошибка «Детский билет нельзя продать…».
9. Выбрать билет в таблице → «Вернуть выбранный билет» → «Да» → место снова зелёное,
   выручка уменьшилась.

## Ответ на контрольный вопрос «Опишите шаблон MVC»

**MVC (Model — View — Controller)** — шаблон проектирования, который делит приложение
на три независимые части:

* **Model (модель)** — данные и логика: хранит информацию, выполняет вычисления,
  следит за правилами. Ничего не знает об интерфейсе. Здесь — `CinemaModel`: считает
  цену, продаёт и возвращает билеты, хранит занятые места и выручку.
* **View (вид, представление)** — интерфейс. Показывает пользователю данные модели
  и принимает его действия (нажатия, ввод). Здесь — окно `MainWindow`.
* **Controller (контроллер)** — обработчик действий пользователя. Получает ввод
  от вида, проверяет его и передаёт модели. Здесь — `TicketController`.

**Как это работает:** пользователь нажимает кнопку во View → View передаёт ввод в
Controller → Controller проверяет его и вызывает метод Model → Model меняет данные
и сообщает об этом → View перерисовывается по новым данным.

**Зачем это нужно:** части можно менять независимо. Например, формулу цены можно
переписать в модели, не трогая окно, а окно перерисовать, не трогая расчёты.
Над разными частями могут работать разные программисты, код проще читать,
проверять и исправлять.
